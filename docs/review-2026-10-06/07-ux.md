## ① 问题清单（按严重度）

### X-1（P1）浮层卡片内点击误关 —— "点外关闭"吞掉点内
`hit_test_all` 命中最深子元素后，`handle_lbutton_down` 向上找最近带 `on_click` 的祖先（Host.cpp:838-848）。overlay 根（scrim / 透明根）带 `on_click` 用于点外关闭，而卡片本体及其非交互子元素都没有 `on_click`，于是**卡片内的任何非交互命中都会冒泡到 overlay 根**；`handle_lbutton_up` 的 inside 判定（Host.cpp:914-922）只检查"按下元素是否为释放点的祖先"，根是万物祖先 → 必然触发关闭。
- modal：点正文任意标签/空白 → 关闭并丢表单内容（Overlays.cpp:260-306，scrim 根 on_click）。唯一不触发的是 Close 按钮与滚动条。
- 命令面板：点提示行 "↑↓ navigate…" 或 "No matching commands" → 关闭并丢已输入 query（Menus.cpp:158-166 + Host 冒泡）。
- drawer：点面板正文文本 → 关闭（Layout.cpp:73-108）。其 × 图标甚至没绑 on_click（Layout.cpp:98-105 只设了 tooltip），目前点击 × 能关纯粹是靠这个 bug。
- 对照：Gallery 手写 popup（Gallery.cpp:1751-1790）同样中招。
[V] 代码链完整。实测尝试见「未验证」——Dashboard 因 04-R1 崩溃、Gallery 因输入冻结（见下）未能留下直接截图。

### X-2（P1）键盘可达性矩阵
collect_focusable 只收 `props.focusable && enabled`（Host.cpp:691-698），而以下组件用 `label`/`view`/`icon` 承载 on_click，全部不可聚焦、无键盘等价：

| 组件 | 载体 | 位置 | 键盘现状 |
|---|---|---|---|
| `ui::tabs` | label | Navigation.cpp:34 | 不可 Tab，无方向键 |
| `ui::segmented`（**含 Gallery 顶级导航**） | label | Navigation.cpp:76 | 同上 |
| `ui::pagination` 页码+前后 | label / `flux::icon` | Navigation.cpp:101,115 | icon 载体连 cursor 都没有 |
| `ui::accordion` 头 | view | Navigation.cpp:153 | 仅 cursor=hand |
| `ui::data_table` 行 | view | Data.cpp:93 | 行选择纯鼠标 |
| `ui::tree_view` 节点 | view | Data.cpp:144 | 展开/选择纯鼠标 |
| `ui::radio_group` | view | Pickers.cpp:52 | 无 roving tabindex |
| `ui::color_picker` 色块 | view | Pickers.cpp:97 | 同上 |
| `ui::date_picker` 日期格 | label | Pickers.cpp:170 | 无方向键无今天键 |
| `ui::breadcrumbs` | label | DataViz.cpp:155 | 同上 |
| `slider`（原语） | — | Host.cpp:103-121 | 可聚焦但无 on_key：←→ 无效，键盘无法调值 |

可达的只有：button / checkbox / toggle（Space/Enter 激活）、scroll_view（聚焦后 ↑↓ PgUp/PgDn Home/End，Host.cpp:1010-1029）、命令面板（input on_key）。**Gallery 顶级 tab 导航本身不可键盘操作** = 键盘用户连换页都做不到。

### X-3（P1）焦点契约三缺陷
1. **首按跳过 order[0]**（Host.cpp:1070-1085）：focus_path_ 为空时 index 默认 0，再 +1 → 聚焦 order[1]。上轮截图证实：`k_00_start.png` → `k_tab_01.png` 差分 bbox=(56,252)-(150,284) = Primary 按钮（order[0] 是 header 主题按钮，被跳过直到整圈环绕）。[V]
2. **modal 无焦点陷阱**（Host.cpp:1062-1067）：Tab 序 = 主树 focusable 在前、overlay 在后 → modal 打开时 Tab 先走完所有背景元素。WCAG 2.4.3 焦点顺序违规。[V]
3. **背景可被键盘激活**（Host.cpp:1088-1093）：modal 打开时 Space/Enter 直接激活 focus_path_ 元素——没有"浮层打开时屏蔽背景 on_click"的判断。打开 modal 的按钮仍持焦点，按 Space 会再次触发它。[V]

### X-4（P2）三态反馈覆盖面
- 原语 `button()`（Host.cpp:35-48）设了文字色/padding/radius/cursor，**不设 background/hover_background/pressed_background** —— 三态视觉完全靠调用方。Gallery 的 4 个样式 helper（Gallery.cpp:97-140）齐了；`flux::ui` 只有 hover 没有 pressed：menu_item_button（Overlays.cpp:45-58）、icon_button（68-79）、modal Close（298-302）、sidenav 项（Layout.cpp:136-154）、calendar 前后翻页（DataViz.cpp:179-192）。
- **死代码三目**：slider 轨道 `(path == pressed_path_) ? pal.surface_variant : pal.surface_variant`（Host.cpp:1519-1521）、toggle 同款（1540-1543）——按下无任何视觉区分，两处本意应是 pressed 变浅/变深。[V]
- 无 hover 的可点击面：tabs、segmented、pagination、表头按钮（Data.cpp:63-79 只设了 tooltip）、表格行、radio 行、色板、日期格（选中才有 accent 底）。
- Motion 页图标网格 24px 图标设了 `hover_background` 却无 on_click（Gallery.cpp:1600-1614）——悬停发亮但不可点，伪可供性。
- 禁用按钮仍显示手型光标（Host.cpp:583-589 的 cursor walk 不检查 enabled）。
- 进度条无 indeterminate 模式、无补间（点击 +10% 直接跳变）——长操作无"进行中"语义可用。

### X-5（P2）校验呈现时机
`form_demo` 每帧无条件跑 `validate_not_empty(form_name)` / `validate_email(form_email)`（Gallery.cpp:1800-1825）→ 首帧即红字（截图 ux5_04/ux6_e1：空表单 + "Name is required" + "Enter a valid email address"）。无 submit 按钮、无 blur 触发、无"输入后错误即时清除"演示（其实输入有效内容会清除，但"未交互先报错"已是反模式）。错误只有红字+红框，无 图标/Summary。`input_error` 仅 text_input 支持 Props.input_error（Element.hpp:108）。

### X-6（P2）信息架构：命令面板空洞 + 发现性

- Dashboard 面板 5 项缺 Servers(1) 和 Billing(3)（Dashboard.cpp:326-337）——恰恰 Servers 是唯一有详情 drawer 的页面。
- 过滤为大小写不敏感子串（Menus.cpp:134-152），无 fuzzy、无 MRU、无分组。

## ③ 理想交互蓝图

**焦点契约**（修复 X-2/X-3 的系统方案）
- 角色化默认值：容器型组件（tabs/tree/menu/select/table）内置 roving tabindex——容器自身 focusable 一枚，↑↓ 移动活动子项，Enter/Space 激活；叶子控件默认 focusable。
- Tab 序规则：声明序 = Tab 序；modal/drawer 打开时 collect_focusable 范围限制在最高层浮层（陷阱）+ 打开前焦点复原。
- 焦点环语义：键盘导航才显示环（:focus-visible 等价），鼠标点击获焦不显示——现在点任何按钮都会留一个常驻环（ux1 系列可见），视觉噪音。
- text_input 双轨合一：Tab 聚焦同时设 focused_input_path_，根治上轮确认的丢键入。

**快捷键注册表**
- `Host::add_accelerator(Modifiers, vk, command_id)`；command_id 与 CommandItem 同源 → 面板自动显示快捷键提示列。
- 保留段：Ctrl+K 面板、Ctrl+1..9 直达 tab/页、Esc 层级退出（已有）、F6 焦点区循环、? 显示快捷键表。
- DESIGN.md 增"键盘契约"一节（现文档零快捷键记载 [V grep]）。

**UIA 分层引入**
- L0（1 天）：WM_GETOBJECT 返回 host 级 provider，Name=窗口标题——读屏至少不再读到空窗口。
- L1（1 周）：焦点变化发 EVENT_OBJECT_FOCUS；为 focusable 元素生成 Name（text/tooltip_text）、Role（type 映射）、InvokePattern——Tab 能被 Narrator 跟随。
- L2（按组件渐进）：StatePattern（checkbox/toggle/select）、ValuePattern（text_input/slider）、ScrollPattern（scroll_view）、表/树的树形 peer。

**反馈组件族规范**（入库门槛）
每个可交互组件必须同时具备：(a) 三态视觉由库统一注入（hover/pressed 不再依赖调用方传 Props）；(b) 键盘等价操作；(c) 无障碍文本（tooltip_text 复用为 help text）；(d) ≥24px 命中区；(e) 禁用态光标与 tooltip 说明原因。可加一个 smoke test 断言：所有带 on_click 的元素 focusable==true（用测试树遍历）。

## ⑥ 建议人工复核清单（本轮合成输入无法定论项）

1. **X-1 卡内误关**：真人鼠标点 modal 正文/命令面板提示行/drawer 正文 → 确认关闭（代码链完整，预期必现）。
2. **图表十字线**：真人鼠标在 line/area 上缓慢移动——本轮两次注入 move 后差分为 0，与 memory 中已确认的 DComp transform bug（局部 dirty rect 内容落点偏移）症状一致，但合成输入（无真实 WM_MOUSEMOVE 序列/无 mouse leave）是混淆因素。
3. **hover/pressed 高亮可见性**：同上——本轮 Gallery 计数按钮点击后 "Clicked: N" 文本未变化（ux7 两次、干净进程），若真人点击也不变，则局部重绘可见性问题比 memory 记录更广（不限于 hover）。
4. **混合交互序列后输入失效**：本轮 Gallery 在 modal 开→Esc→scrim 关→再点击/滚轮的序列后，后续所有合成输入无响应（ux5_b 系列）；单纯序列（theme→tab→滚轮）正常（ux5_a）。疑与 04-R2（嵌套重绘自毁闭包）同族，建议与 04 联合复现。
5. DPI 125/150%：本轮会话仅 96 DPI 单显示器（GetDpiForWindow=96），未测。
6. 真实键盘 Tab 长循环 + 读屏器（Narrator/NVDA）冒烟——预期零播报。
