## 0. 一页结论

### 因果链

WinFlux 的核心模型——单 HWND、每帧重建树、damage 局部重绘——**本身被实测证明是高效且正确的**（build≈0.001ms、damage≈0.007ms、CPU 每帧实耗 ~3ms，hover 反馈 <1 个 vsync）。问题不在渲染内核，而在包裹它的三层契约缺失：

1. **生命周期收口缺失** → 用户可直接感知的崩溃与异常：关窗后所有应用进程僵尸（R-3，全仓无 `PostQuitMessage`）；handler 内改 State 会销毁正在执行的闭包（R-2，11 个分发点的系统性 UAF）；Dashboard Servers 页每帧数组越界（R-1，你桌面上的断言弹框本体）；双 Esc 解引用空 optional（R-4）。
2. **交互契约缺失** → 所有下游应用继承缺陷：浮层卡片内点击冒泡误关（X-1）；键盘可达性系统性缺失（14 个交互组件 10 个不可 Tab，顶级导航都不可键盘操作，X-2）；Tab 首按跳过第一个元素、modal 无焦点陷阱（X-3）；Esc 关浮层无重绘反馈（R-5）；无障碍零基础（无 UIA/MSAA）。
3. **扩展无保护** → 债务复利：元素 type 是 27 处运行期字符串比较、`paint_props_equal` 靠人肉 5 步清单、设计 token 三副本手工同步——每个新功能都在无回归网的状态下加码（交互/渲染核心 ~2500 行在 CI 零断言，`WINFLUX_SKIP_GUI_TESTS` 把生命周期测试整个短路）。

**CI 的 61 个绿灯 commit 掩盖了这一切**：GUI 测试在 CI 永不执行，样例不进 CI，R-1 这种"打开页面必现"的缺陷因此在仓库里存活了 8 个 round。

### 1.3 更正记录

1. **「弹框是探针、不是产品崩溃」→ 更正**：主审最初向用户如此解释；实际是 04 的探针复现了产品自身的 R-1（Dashboard Servers 页每帧触发同一断言），且样例僵尸进程（R-3）加剧了"一直有崩溃"的观感。以代码证据为准。

3. **06「CI 零断言」与 04「测试全过」并存的口径**：本机有窗口站，lifecycle 7 个 check 全过（04 实跑）；短路只发生在 CI runner 无窗口站环境。两者不矛盾。
4. **性能维度执行者变更**：02 两次派发均被 429 中断且未落盘，最终数据由主审实测产生（标注于分报告头部）。

## 3. 性能（主审代跑，详见 02 分报告）

实测结论：帧管线 CPU 实耗 ~3ms（build 0.001 / layout 2.5 / damage 0.007），"draw" 的 8-25.7ms 主体是 DComp 合成同步等待（Release 因 CPU 更快、帧提交饱和而呈现更长等待——与首轮代理死前实测及 08-15 历史日志三方互证）。空闲零开销。**性能不是当前主要矛盾**；可观测性（120 帧粒度、无分位数）与规模外推（layout 无增量）是仅有的两个真实议题。优化方向应据此校准：省 CPU 不省 wall-clock，省 GPU/脏区面积才省。

## 4. 架构工程（详见 06 分报告）

健康度 6.5/10（B−）。亮点：include 图零环、单向分层属实、零警告、注释讲 why、演进纪律好（10 项值得保留实践清单见分报告 §8）。债务 Top：Host.cpp 上帝对象（12 职责簇 1615 行）、新增基础元素霰弹式修改零保护、交互渲染核心 ~2500 行 CI 零断言、异常策略矛盾、token 三副本（+nfui 第四份无机制）、presenter 无法注入、混行尾 25/48。演进路线 R1-R12 按 ROI 排序（分报告 §9），首选：R2 修 radar → R5/R6 异常与断言 → R7/R9/R10 契约基建 → R1 props 默认反转 → R4 测试网 → R3 最后拆 God file。

## 5. 交互与人体工程学（详见 07 分报告）

Top 5：X-1 浮层卡内误关（P1）、X-2 键盘可达性系统性缺失（P1，含 Gallery 顶级导航）、X-3 焦点契约三缺陷（P1）、X-4 三态反馈覆盖不全（P2）、X-5 校验时机反模式（P2）。另有点击目标尺寸（splitter 6px）、toast 层级倒置、窄窗降级缺失、无障碍零基础（"Enable animations"是安慰剂 State）、五类浮层行为对比表、快捷键核对表（Ctrl+S 提示文案是文档谎言）等 17 组。竞品共识：**键盘/无障碍是组件库入库门槛而非附加项**——这是 WinFlux 与 Qt/WinUI/Flutter 的最大差距。

## 6. 功能扩展（详见 08 分报告）

现状盘点：40+ 组件/原语中 ~28 成熟；立项文档愿景 vs 实现差距表逐项核实（M4 承诺的 PropertyGrid/IconView/命令路由/持久化/UIA 全部未交付；IME 停留；nfui 图表高级交互全缺；"key/reconcile M2 引入"从未实现）。Top 10 推荐：文本输入 Phase1（选区/剪贴板/placeholder）→ 事件原语补全（双击/元素右键/拖拽）→ CMake 消费化+README → 持久化原语 → 调试 HUD → IME → 快捷键注册表 → 主题系统集成（深色标题栏）→ 焦点管理器 → 图片/图标+系统对话框。明确不做：打印、热重载、跨平台、TSF 全量、主题文件格式。每项附性能护栏（如 caret 闪烁必须局部动画，不得走 animating() 全屏脏）。
